🎯 Project Mission

Modernize corporate training governance at FHC by replacing decentralized spreadsheets with an automated, auditable, and workflow-driven ERP system that tracks courses, enforces trainer schedules, evaluates scores, and manages certificate expirations.

Strategic Context

Problem Statement & Objectives

Why FHC needs a dedicated Training & Certification Management solution

⚠️ Existing Operational Pain Points

  • Disparate Records: Employee training history, attendance, and scores fragmented across department spreadsheets.
  • Trainer Double-Booking: Overlapping training sessions scheduled without calendar collision checks.
  • Compliance & Safety Risk: Expired safety and engineering certifications go untracked, risking regulatory non-compliance.
  • No Approval Hierarchy: Training budgets and sessions committed without formal managerial review.

🎯 Core System Objectives

  • Relational Master Data: Structured Courses, Instructors, Sessions, and Certificates with strict foreign keys.
  • Enforced Workflow: Multi-state approval hierarchy (Draft → Pending Approval → Approved → Completed).
  • Zero-Conflict Scheduling: Server-side collision detection preventing trainer over-scheduling.
  • Automated Expiration: Daily cron task flipping past-due certificates paired with dynamic expiry reporting.

🔗 Relational Integrity Highlights

Every participant row in a session links forward to their issued Certification, and every Certification points back to the course and session. Duplicate certificate creation for the same session and attendee is blocked by database constraints.

Process Governance

Business Process & Multi-State Workflow

Workflow Name: Training Session Approval with clear state boundaries

🔄 State Transitions

  • Draft → Pending Approval: Submitted by Training Officer. Validates participants > 0.
  • Pending Approval → Approved: Approved by Training Manager. Locks trainer calendar.
  • Pending Approval → Rejected: Rejected by Manager. Officer can click "Revise" to return to Draft.
  • Approved → Completed: Executed by Trainer/Manager once End Date is reached.
  • Approved → Cancelled: Executed by Manager if training is called off.

🛡️ Critical Guardrails

  • No Empty Submissions: A session cannot transition to Pending Approval without at least one participant.
  • Premature Completion Guard: Complete action is blocked if current date < Session End Date.
  • Calendar Reservation: States Pending Approval and Approved actively block overlapping bookings.
[Draft] --(Submit: Officer)--> [Pending Approval] --(Approve: Manager)--> [Approved] --(Complete: Trainer/Mgr)--> [Completed]

                                (Reject: Manager)                         (Cancel: Manager)

🔒 Row-Level Query Hook Implementation

def get_permission_query_conditions(user=None):
    user = user or frappe.session.user
    if "Trainer" in frappe.get_roles(user) and user != "Administrator":
        trainers = frappe.get_all("Trainer", filters={"user": user}, pluck="name")
        quoted = ", ".join(frappe.db.escape(t) for t in trainers)
        return f"`tabTraining Session`.`trainer` in ({quoted})" if quoted else "1=0"
    return ""

1. Double-Booking Conflict Prevention

clash = frappe.get_all(
    "Training Session",
    filters=[
        ["trainer", "=", self.trainer],
        ["name", "!=", self.name or ""],
        ["workflow_state", "in", ["Pending Approval", "Approved"]],
        ["start_date", "<=", self.end_date],
        ["end_date", ">=", self.start_date],
    ],
    pluck="name", limit=1
)
if clash:
    frappe.throw(_("Trainer {0} booked in {1}.").format(self.trainer, clash[0]))

⚡ Live Calculation on Row Edits

frappe.ui.form.on("Training Participant", {
    score: recalc_row,
    attendance: recalc_row
});

function recalc_row(frm, cdt, cdn) {
    const row = locals[cdt][cdn];
    let result = "";
    if (row.attendance === "Present") {
        result = flt(row.score) >= flt(frm.doc.passing_score) ? "Pass" : "Fail";
    }
    frappe.model.set_value(cdt, cdn, "result", result);
    update_summary(frm);
}

Engineering Insights

Challenges Encountered & Technical Solutions

Overcoming real-world architectural and Frappe development constraints

1. Trainer List Leakage

Challenge: Standard DocPerm rules allowed trainers to see other instructors' scheduled sessions in the desk list view.

Solution: Hooked into permission_query_conditions to dynamically inject SQL clauses matching the trainer's linked user.

2. Date Interval Clashes

Challenge: Simple equality matching missed multi-day overlapping sessions starting or ending mid-schedule.

Solution: Implemented mathematical interval intersection (start_date <= other.end AND end_date >= other.start).

3. Certificate Idempotency

Challenge: Repeated clicks on "Issue Certificates" could produce duplicate certificate records.

Solution: Embedded foreign key certificate link directly on the child table row and enforced unique session-participant constraints.
